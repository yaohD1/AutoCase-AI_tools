# 生成流程对比测试方案（正确性单维度）

> 目标：只回答一个问题——**哪个流程写出的脚本能跑通。**
> 环境已验证：人工 baseline 9 步全通，32 秒 PASS。

---

## 1. 判据只有一个

**真跑。PASS 或 FAIL。**

不看写法是否符合项目习惯、不看注释好不好、不看有没有 Suite Setup。跑得通就是对，跑不通就是错。静态检查只用来解释 FAIL 的原因，不参与评分。

---

## 3. 两组输入

| | A · 现状 | L · 精简 |
|---|---|---|
| 提示词 | **56,673 字符** | **7,808 字符** |
| 派单内容 | 9 步 + 任务书 + 176 条 SeleniumLibrary 关键字 + 框架方言 3,928 字 + 定位规则 + 2 篇样例 + 项目画像 + toolchain | 9 步 + 任务书 + target_path |
| agent | `recording-emitter`，12,128 字符，含全部 RF 方言映射 | 1.2K，只说「先读项目、按录制定位写、只写 target_path」+ 两条生命周期规则 |

L 的两条生命周期规则：
1. 不写 `Suite Setup`（录制里已经有登录，再写就是双重登录）
2. 写 `Suite Teardown    关闭浏览器`（录制不关浏览器）

可选 **L0**：L 去掉这两条规则，完全裸奔——用来回答「精简后是否必须补规则」。

## 4. 执行

```
每组：生成 → 真跑 → 记录
1. 生成一次，产物落 测试用例层/_promptlab/<组>.robot
2. 真跑：robot --pythonpath <stub>，AUTOCASE_DOWNLOAD_DIR=~/Downloads
3. 记录：PASS/FAIL、失败步、耗时、脚本行数、提示词字符
4. 清理 Downloads 里的导出文件
```

A 组如果复用已有产物（`A-现状.robot`，上一轮生成），成本为零；重跑一次则保证同批次。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 滑块替身与真实算法不同 | 所有组用同一个替身，对比较公平；baseline 已证明 180 能过 |
| 模型随机性 | 每组跑 1~2 次，记全部结果，不挑选 |
| 真跑有副作用（登录、写 Downloads） | 每次跑完删导出文件；不修改被测系统的数据（只读页面 + 导出） |
| 首次跑会慢（登录里 `Sleep 7` + 33 次退格） | 单次 30~40s，可接受 |
