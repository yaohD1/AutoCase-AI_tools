## 规划轮和写入轮合到同一个 opencode session

用户原话：「给到定位后 他自己收到任务要求自己去读取项目，然后开始编写文件，这些我希望在一个 session 里」。

### 为什么不是「一个 serve 走到底」

opencode 的 agent 权限是 **serve 启动时**加载的，而收窄的写入路径要到任务书轮结束才知道。
硬要一个 serve 就得一开始把 emitter 的写权限开成 `*`，等于放弃「只准写一个文件」。
所以做成 **一个 session + 两个 serve**。

`shots/_check_emit_session.py` 在 **1.18.31** 上实测六项全过：
新 serve 能续上旧 session（GET 200、消息条数 3→3、第二轮准确复述第一轮读到的 token）、
同一 session 换 agent（planner → emitter → build）成立、收窄配置对续上的会话生效
（build 写非目标文件被拒，工具返回里带规则原文）。

### 两个踩到的坑

1. **`POST /session` 和 `prompt_async` 的 model 形状不一样**：
   建会话要 `{id, providerID}`，发消息要 `{providerID, modelID}`。传 `modelID` 给建会话
   直接 400 `{"_tag":"BadRequest"}`。`_split_model` 返回的就是 `{id, providerID}`，别自己拼。
2. **续上的会话里模型不再核对目录**：它以为 `tests/` 不存在，试图 mkdir，被权限拒绝，
   报「父目录不存在」——目录其实在。提示词里补了「直接写 target_path，不要为它新建目录」。

### 降级与生命周期

- 三级：续上 `scoped=True`；续不上/消息数变少 `scoped=False`（退回规划期 serve，靠 guard 兜底）；
  serve 死了 `reused=False`（退回一次性生成）。
- `begin_write` 必须比对 `GET /session/{id}/message` 条数：只看 200 会把「壳回来了、
  工具 part 没回来」当成续上，写手拿着空上下文写出一份「看起来像」的脚本。
- `/plan` 建，`/generate` 的 finally 关；文件冲突 409 不关；新录制开始 close_all；
  1h 空闲 / 4h 上限 / 8 轮上限兜底。

### 顺带修掉的两个老问题

- 刷新页面丢任务书：`progress.remember_plan()` → `/recording/current` 的 `emit.plan`，
  前端 `applySession` 恢复。以前刷新必须重新规划 = 重读一遍项目。
- 规划轮没有取消入口：新增 `POST /automation/recording/emit/cancel`。

### 提示词

- planner 的「最多 4 个文件 / 4 轮工具调用」删掉，改成「不设硬上限，但要收敛，15 分钟内」。
- 写手第二轮加短头：不要重新扫项目、不要输出任务书、直接写文件、不要建目录。
- `write_scope=instruction_only` 时「runtime 强制」改成「仍只能写 target_path，越界会被记录」。

### 真机验证踩的坑（都是验证脚本的问题，不是产品的问题）

用 `shots/_check_emit_session_live.py` 跑生产类时，写入连续失败四次，每次原因都不一样：

1. 「没有提供 target_path」——dispatch 里没写；
2. 「父目录不存在」——模型没核对就直接判断；
3. 「权限规则拒绝」——**工作区不是 git 仓库**，`apply_patch` 按 worktree 算相对路径，
   算出来的是 `ac-live-xxx/tests/a.spec.ts`，所有白名单都命中不了；
4. 「没有 write 工具」——我自己在提示词里写了「用 write 工具」，而 1.18.31 里
   唯一的写工具叫 `apply_patch`，等于告诉它工具不存在。

第 3 条是关键：**写权限的相对路径按 git worktree 算，不是 cwd**。真实流程里
`validate_workspace` 强制「git 仓库根」，所以生产没问题；写验证脚本必须先 `git init` + commit。
补上 git 之后五项全过（读 token / 换 serve 续会话 / 复述 token / 写入文件 / 两轮记录）。

第 4 条也进了提示词避免再犯：**不要写「用 write 工具」**，也别往 permission 里塞
opencode 不认识的 key（`apply_patch`），那会让整个 agent 的工具清单变空。

## 去掉「只准写一个文件」的硬约束：一个 serve + 手动还原

用户原话：「现在是一个session 两个server？是因为写权限的原因才能两个server吗 … 我觉得这个只允许写入目标文件这个规则太硬性 … 改成全工作区+允许手动还原就可以，他脚本可能还有一些需要写入封装文件」。

### 结论：一个 serve 就够，只要写权限不再依赖 target_path

`_emit_config(writable, workspace, scope=)` 现在有两档：
- `workspace`（默认）：`edit`/`write` 全工作区 allow，只 deny `.git`、`.opencode`、`node_modules`；
- `file`：旧的单文件白名单，留作保底。

规划轮就能用最终那份宽配置起 serve（planner 本身只读），写入轮换 emitter 即可，
`begin_write` 不再重启进程，只返回 `{reused: True, scope: 'workspace'}`。
`scoped` / `context_suspect` / 消息数比对那一整套换权限降级全部删掉，只剩「serve 死了退回一次性生成」。

### 为什么这条硬规则本来就该松

不是「太严」，是「看着严、实际脆」：
1. 白名单按 `path.relative(worktree, filepath)` 匹配，工作区不是 git 仓库根时一条都命中不了（验证脚本连踩三次）；
2. 1.18.31 上模型实际调用 `apply_patch`，它的路径检查和白名单对不上，被误拒过；
3. 它只覆盖 edit/write/apply_patch 三个工具，拦不住任何别的通道。

### 越界改成「清单 + 手动还原」，不自动还原

`guard.capture()` 在生成结束时把越界文件在**快照时刻**的内容导出到
`.autocase/backups/<id>/manifest.json`（`restore` 有原内容 / `delete` 是新建 / `skip` 拿不到）。
**导出必须紧接生成结束**：`stash create` 的 commit 没有 ref，git gc 之后就取不到了。
`guard.revert()` 按清单还原，还原前把当前内容存到 `current/`，误点了能捞回来。
不自动还原的理由：模型确实可能需要写 helper，自动删会把有用的东西一起删，也会误伤用户同时的编辑。

### bash 保持 deny（用户中途改主意，实测支持这个决定）

试过放行 `npx playwright test*`，1.18.31 上的实测结果：

| 命令 | 结果 |
|---|---|
| `npx playwright test --list` | 执行 |
| `npx playwright test --list --reporter=line` | 执行 |
| `cd . && npx playwright test --list` | 执行 |
| `npx playwright test --list 2>&1 \| tail -5` | **被拒** |
| `npx playwright test --list; echo done` | **被拒** |
| `echo probe > ac-x.txt` | 被拒 |

关键：**管道会被整条拒掉**，而模型看测试输出几乎必然加 `2>&1 | tail`，每拒一次浪费一轮。
好处是证明了 opencode 会解析 `&&` / `;` / `|` 后逐段校验，不是简单字符串前缀匹配——
`npx playwright test --list && echo x > y` 整条被拒，所以「只放行测试」在安全上是成立的，
只是不好用。验收本来就在后端跑，没必要把这活交给模型。

### 两个容易搞混的开关

- **`tools.bash = false` 和 `permission.bash = deny` 是两件事**：只改 permission 不打开 tools，
  工具根本不会出现（模型会说「我没有 bash 工具」，看着像权限，其实是没这个工具）。
- 给 `apply_patch` 加 permission key 会让整个 agent 的工具清单变空——1.18.31 不认这个 key。
  `edit` 权限已经覆盖 edit / write / apply_patch 三条途径，不要再单独写。

### 提示词

`recording-emitter.md` 的 `# Scope (hard rules)` 整段重写：主文件是 target_path，
确实需要辅助文件可以写但要逐个说明用途、必须放同一个测试目录、能内联就内联，
不许改 package.json / 配置 / 其他已存在的测试文件。
`LOCATOR_RULES` 里那句「只写 target_path、写别的会被拒绝」删掉了——它在新规则下是矛盾的。
`_prompt()` 按 `write_scope` 分三支：`workspace` / `exact` / `instruction_only`。

## 封装动作（步骤合体成一个可调用动作）

用户要「4 步合体成 1 步、后续能直接调用」。三个方案里选了 **B 具名动作**：
工具栏多选 → 封装弹窗（动作名 / 说明 / 参数表）→ 原位置变成调用卡；
动作存项目级 `<工作区>/.autocase/actions.json`，输入值默认全部变参数。

关键决策与踩到的坑：

- **生成时 call 绝对不能展开**。展开成平铺 4 步，写手就会真写 4 行重复代码，
  封装等于白做。`_payload` 另给 `actions`（子步骤定位 + `{{key}}` 占位 + `called_at`），
  提示词写死「同一动作的多次调用必须复用同一个函数」。回放反而必须展开（`replay._expand`）。
- **只能选连续区间**。非连续合体后顺序不是用户看到的那顺序。`_tied_range` 会把
  区间扩到不切断「点击 → new_page」的绑定；含 call 的区间禁止再封装（不嵌套）。
- **参数名别用中文别名硬转**。别名是「用户名」，但快照 `snap.name` 往往就是
  `username`——按 name → placeholder → id → alias 的顺序挑第一个能 ASCII 化的。
  取不到才退回 `arg` / `arg2`。
- **`el-popover` 里的 `primary + plain` 按钮会变成蓝底蓝字**（文字完全看不见）。
  全站那份兜底规则写在 `:is(.ui-buttons, .list-page, .el-dialog)` 下，浮层被 teleport
  到 body，够不着。给 popper-class 加 `ui-buttons` 即可，别再单独调颜色。
- `mock.patch.object(emit, 'generate')` 的测试替身**写死了形参表**，新增 `actions`
  参数后 11 个用例一起挂，报错是 `generate() got an unexpected keyword argument`。
  以后给 generate/plan 加参数，先 grep 测试里的 `def generate(runner`。
- 真机生成验证**没跑成**：本地两个模型（opencode/beam-free、cctq-codex/gpt-6-luna）
  都是 90 秒无响应，`ask_text` 直接 Read timed out。载荷形状与提示词用
  `shots/_check_action_prompt.py` 静态核对通过，模型是否照做仍待真实环境确认。
