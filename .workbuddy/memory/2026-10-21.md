## 移除录制工具栏的「取消」按钮

- 背景：「取消」与「停止录制」实际差别只有 ①不重校验定位 ②`cancelled` 状态下生成接口 409；而且 cancel 并未清空 `_steps`（实测取消后步骤仍在快照里），前端 `canEdit` 又不含 `cancelled`，结果是一堆看得见但按钮全灰的死内容，文案「丢弃全部步骤」也不成立。
- 改动：
  - `Recording.vue`：删掉工具栏 `取消` 按钮与 `cancelRecording()`（含 ElMessageBox 二次确认）。
  - `api/index.js`：删掉 `cancelRecording()`。
  - `routes/recording.py`：删掉 `POST /api/automation/recording/cancel`。
  - `session.cancel()` **保留**，标注为内部「关浏览器但不重校验」的快捷出口（`test_recording_routes` 的 teardown 在用）。
  - `AGENTS.md` 补一条说明。
- 验证：工具栏录制中为 [停止录制, 暂停录制, 拾取元素, 添加断言, 添加等待, 固定等待]（无取消），点停止后变 [开始录制, ...] 且 status=stopped、无 page error；44 测试 + build 通过。

## 录制页（/recording 普通模式）首屏重构：从 2.3 屏压到 1.1 屏

- 问题实测（1440×900）：页高 2109px；顶部标题+说明 156px；「目标与配置」卡 719px（7 字段垂直堆叠、输入框 809px 宽）；右栏「工作区检测」485×622px 只放 3 行字；空态步骤卡 346px（el-empty 大插画）；生成卡 283px（4 条未满足检查）；**「开始录制」在 y=1090，折叠线下 190px**，首屏点不到。
- 改动（只动普通模式，panel/embed 的 600px 面板不受影响）：
  - 页头：`.page-header` 77px，两段说明合成一段（第二段进 `?` tooltip `hint-dot`），右侧 `.page-actions` 放「开始录制/停止录制」（随状态切换）+「返回首页」。
  - 配置：`el-form` 改两列网格 `.config-form--grid`（起始地址/工作区/目标文件 `span-2` 整行，框架｜模型、目标文件｜用例名称 同行），Python 解释器进「高级设置」`showAdvanced`（默认收起）。
  - 检测：删掉常驻右栏，结果内联成 `.detect-inline` 的 chips（框架/Python/SeleniumLibrary），细节折进「依据与参考文件」的 `<details>`；Python 路径用 `tailPath()` 只显示末两段、完整路径放 title。
  - 空态：`el-empty` → `.steps-empty` 一行虚线提示（346 → 186 卡高）。
  - 生成卡：未停止时 `.gen-compact` 一行（停止后可生成 · 已录 N 步 · 定位不唯一数），停止后才展开 `.checklist`（283 → 211）。
  - 工具条里的「开始录制」在普通模式降级为 default（避免和页头 primary 抢视觉）；panel 模式仍是 primary。
- 坑：`.el-form-item__content` 默认横向 flex，`field-hint` 和检测 chips 会被排到同一行，必须 `flex-direction:column`。
- 结果：页头 156→77、配置 719→486（检测后 556）、步骤 346→186、生成 283→211、整页 2109→1680（生成记录 665 未动，属方案 B）；「开始录制」y=118 首屏可见。
- 验证：1440/1280/1000 三档宽度（1000 时配置单列 878px）、嵌入面板 600px 单列无横向溢出、页头起停录制正常（录制中→已停止）、检测 chips 正常、高级设置可展开、无 page error；`npm run build` 通过。

## 录制页二改：左右两栏一屏工作区 + 生成记录独立成页

- 需求：信息密度再提高；生成记录单独跳页；左配置、右「步骤+生成」。
- 实现
  - 新页 `views/RecordingRecords.vue` + 路由 `/recording/records`：340px 列表 + 详情，`max-height:calc(100dvh - 320px)` 各自内部滚动；默认选最新一条（带 `?id=` 选中指定），提交/撤回/预览逻辑从 Recording.vue 整体搬过来；50 条记录时整页仍 900。
  - `Recording.vue`：删掉 records 全部 state/函数/CSS（约 200 行）；`.recording-body` 左 400px 配置 + 右 `.main-layout`（steps flex:1 + generate 贴底）；页头加「生成记录」按钮（Tickets 图标）；生成成功后改跳 `?id=<generation_id>`。
  - 一屏锁定：`.recording-page:not(.is-panel):not(.is-embed) { height:calc(100dvh - 116px) }`（App.vue 新增 `is-workspace`：/recording* 时 el-main padding 收到 22px、body margin 0）。
  - **高度链的坑**：root → `.page-col` → `.recording-body` 三层，任何一层断掉就失效；且 grid 必须 `grid-template-rows:minmax(0,1fr)`，否则 auto 行按内容撑高（14 步时 body 变 1260px、生成卡被推到 y=1190 视口外而 docH 仍 900——看不见也点不到）。排查时用 getBoundingClientRect 找 bottom>视口 的元素最快。
  - 密度微调：card body padding 20→14/16、header 15→11、timeline gap 10→8、step padding 12→10。
- 结果（1440×900）：docH 恒 900；录制页布局 = 左配置(400×640) + 右步骤(479) + 生成(191)；14 步在卡片内滚动；停止后 checklist 展开、生成卡 263；记录页 50 条一屏内。
- 回归：`?id=` 定位、无 id 默认最新、嵌入面板 540px 列宽配置收起/步骤填充/无横向溢出、无 pageerror；`npm run build` 通过。
