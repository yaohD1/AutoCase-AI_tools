## 定位降级：不唯一不再阻断生成（第一批）

- 原行为是双层硬拦：前端 `generateBlockReason` 禁用按钮 + 后端 `emit.generate` 抛 EmitError（"有一步不唯一就整体拒绝"），20 步里 1 步坏就全废。
- 现在改成「降级生成」：
  1. `locators.best_effort(framework, counted)`：取目标框架下 `count > 0` 且 count 最小的候选（同 count 比语义优先级）。
  2. `session._count(frame, specs, mark)`：录制时算 index。**做法**：recorder.js 在 `snap()` 里给目标元素打临时属性 `data-autocase-target=<随机>`（`snap._mark`），Python 用 `locator.evaluate_all(FIND_INDEX_JS, mark)` 在页面里 `findIndex`，算完 `CLEAR_MARK_JS` 摘掉。Playwright 语义选择器的内部排序拿不到，这是唯一可行路径。实测 3 个同名按钮 → index=1 正确、标记清理干净、找不到返回 -1。
  3. `emit._locator_info()` 返回 `{locator, matches, nth, mode}`；提示词每步带 `match_count` / `nth` / `candidates`（最多 5 条），并加了 PROMPT_RULES 让模型写 `.nth(n)`、没有 nth 就 `.first` + 注释。
  4. 只有「一条候选都命不中」才拒绝（错误前缀 `missing:`），因为那种情况写不出任何定位。
- `_revalidate_all` 复核时按 desc 把旧 index 带回来（复核时临时标记早没了，不带就丢降级信息）。

## 定位投影覆盖对齐 + 不变量测试（第二批第一刀）

- 问题：`build_specs()` 的 RF 组门槛写死（`tag in ('button','a')` 才出文本 xpath、`tag=='input'` 才出 placeholder），导致 `div role=button` / `li` / 图标按钮 / `data-testid` 的 span 全部只剩 `rf_css`。快照里明明有 role/aria-label/testid，只是没投影。实测 8 种常见元素里 4 种 RF 只有结构定位 → 「换框架」= 换定位质量。
- 改法（纯 locators.py）：RF 组新增 `rf_testid` / `rf_aria` / `rf_label` 三种 kind，`RF_PREFERENCE` 改为 `rf_testid > rf_id > rf_name > rf_aria > rf_label > rf_xpath > rf_css`（前端 `RF_ORDER` 同步）。投影项：`//*[@data-testid=..]`、`//*[@id=..]`、`//*[@name=..]`、`//*[@aria-label=..]`、`//*[@id=//label[normalize-space(.)=..]/@for]` 与 `//label[..]//*[self::input or self::textarea or self::select]`（两条，命中 0 的自然被跳过）、`//*[@placeholder=..]`、`//*[@role=R][normalize-space(.)=T]`（仅显式 role）、`//tag[normalize-space(.)=T]`（TEXT_TAGS 白名单，故意不含 div，避免 `//div` 把祖先容器算进来）。
- recorder.js 的 `snap()` 新增 `aria_label` 与 `role_attr` 两个原始字段。**role_attr 必须单独存**：`role` 字段是显式 role 或隐式角色合并后的值，用它生成 `//*[@role=..]` 会对真实 `<button>` 生成命中 0 条的候选。
- 新增 `backend/test_recording_locator_parity.py`（不变量测试）：真浏览器 + fixture 页面，12 种元素上断言 ——① 两边都有 count==1 的候选；② 两边选中的候选命中的 data-idx 必须正好是目标；③ 有语义信号时 RF 不许落到 rf_css；④ RF 组任何「恰好唯一」的候选都不许指错元素。另有重复按钮用例断言两边一致回退到结构定位。
- 实测：8 种元素 RF 组 `rf_css` 兜底 4/8 → 0/8；后端 71 项测试全过；真实录制流程复测（div role=button / testid span）新候选 count=1，`rf_testid` / `rf_xpath` 排到 RF 组首位。
- 已知反向不对称：checkbox 只有 name 时 PW 组只剩 css（`get_by_role` 需要 name，而 input 的 snap.name 为 null）。这次没动，属于 PW 侧补候选的活。
- 提示词：`PROMPT_RULES` 拆成 `LOCATOR_RULES` + `FRAMEWORK_RULES[framework]`。RF 段强调「SeleniumLibrary 没有自动等待，每条交互前 Wait Until Element Is Visible，禁止用 Sleep 代替」，并给了 visible/hidden/text_contains/text_equals/value_equals/url_contains/enabled → SeleniumLibrary 关键字的映射表；PW 段给 expect/auto-wait/frameLocator。nth 在 RF 侧统一成 `xpath=(<原表达式>)[n+1]`，不再让模型自由发挥。
- 上下文进提示词：`_steps_for_prompt` 现在带 `page_index`（>0 才带）和 `target.frame{url,name}`。此前 frame_url 只存在后端 IR 里，模型完全不知道元素在 iframe 内，会写成顶层定位。`session` 侧新增采集 `frame_name`（SeleniumLibrary 的 Select Frame 认 name/id 不认 url）。主框架不带 frame 字段，避免模型多写一层切换。

## 生成后回放校验（第三批）：两个框架都能校验定位

- 关键判断：`replay.py` 回放的是录制 IR，不是生成的脚本。所以它验证的是「定位还能不能命中」，而 RF 的 rf_* 候选本来就是用 Playwright 的 `xpath=` / `css=` 数的 → **RF 也能回放，不需要 Selenium**。运行生成的 .robot 才需要 Selenium 环境，那部分才是置灰项。
- `replay.py` 改造：
  - `choose_locator(target, framework)`：PW 用 `target['primary']`（保持原行为），RF 改用 `pick_for('robot-selenium')` → `best_effort('robot-selenium')`（不唯一时降级，和生成一致）；都没有就退回 primary（老 IR 兜底）。
  - `_locator` 返回 `(locator, chosen)`，`_run_step`/`_assert` 透传 framework。
  - `_frame_of(page, snap)`：先按 `frame_url` 全等，再按 `frame_name` 兜底（SPA 换路由时 url 对不上）。
  - `_entry()` 生成报告行：`{no, type, alias, url, ok, error, used:{kind, desc, syntax, matches, nth, degraded}}`。**nth 是 1 基**（生成侧 `degraded` 的 nth 是 0 基，注意别混），`syntax` 是真正写进脚本的写法，前端拿它和生成结果对照。
  - `replay(steps, headless=True, framework=...)` 保持返回 int（旧测试断言 `== 10` 不变）；新增 `replay_checked()` 返回 `{ok, done, total, steps, error, failed_no}`，失败不抛异常 —— 前端要显示「前 9 步走通、第 10 步失效」。`ReplayError` 新增 `step_no` / `step_type` 属性。
- 新路由 `POST /api/automation/recording/replay`：body `{framework, headless?}`。未停止 409、非法框架 400、空步骤 400、回放失败仍 **200**（不是接口错误，是录制本身的问题）、浏览器起不来 500。
- 前端：结果卡「查看生成记录」旁加「回放校验」按钮。`replayFramework` 取 `genResult.framework`（不是当前 config，否则生成后改下拉会校验错框架）。通过 → 绿点 + 折叠；失败 → 红点 + 自动展开 + 失败行标红并在下一行显示原因。明细每行显示 `序号 | 类型 | alias(或 URL) | 定位语法 | 匹配 N 取第 k`。RF 时加一行说明「Robot 脚本需要 Selenium 环境运行，这里只校验定位是否仍然有效」。
- 测试：`test_recording_replay` 加 2 条（RF 报告里 all used.kind 必须 `rf_*`，且 `used.syntax` 必须等于 `_locator_info()` 给提示词的 locator —— 这条守住「回放用的定位 = 生成的定位」；失败保留前序成功步骤）。新增 `test_recording_replay_route.py` 8 条。后端 81 项全过。
- 真实闭环（非 mock，起真实录制 + 真实回放）：7 步录制，PW 与 RF 各回放一次全部 7/7 走通；RF 实际用的是 `rf_id / rf_name / rf_xpath / rf_testid`；把第 4 步候选改成 count=0 后返回 `ok=false, failed_no=4`。
- 已知遗留（非本次引入）：`select` 没有 label/aria 时 PW 组只剩 `css`（`getByRole('combobox')` 缺 name），RF 侧有 `rf_name`。属 PW 侧补候选的活。

## 补 PW 侧候选缺口：role_bare（本次收尾）

- 现象：`select` 没有 label/aria、`checkbox` 没有 label 时，PW 组只剩 `css=html > body > select`。原因是 `build_specs` 只在 `role and name` 同时成立时生成 role 候选，而 input/textarea/select 的 `snap.name` 故意不取文本 → 无 label 时 name 为 null。
- 改法：新增 kind `role_bare`，`PW_KINDS = ('testid','role','label','placeholder','role_bare','text','css')`。`build_specs` 改成 `if role and name ... elif role ...` 生成 `getByRole('combobox')`（无 kwargs）。
- **排序位置很关键**：role_bare 必须排在 placeholder 之后。否则 `getByRole('textbox')` 会盖过 `getByPlaceholder('密码')` —— 有名称的定位永远更强，用「页面上只有一个」作依据是更弱的证据。前端 `PW_ORDER` 同步。
- 不标 fragile：`count == 1` 就是唯一，且它是语义定位。若页面以后新增同类控件，count 变 2 会走 index 降级，不会静默点错。
- 前端徽标仍是「唯一」，但加了 `statusHint()` 的 title：「按 role 定位：页面上只有这一个同类元素。新增同类控件后会退化为…」。四个字的徽标说不清前提，title 补上。
- 测试：core 加 2 条（无 name 出 role_bare 且无 kwargs；有 name 不出；role_bare 排在 placeholder 之后），parity 加 2 条（**PW 侧对称的「唯一候选不许指错」**——之前只保护了 RF 侧；无 label 的 select 必须走 role_bare 而不是 css），并修掉了 parity 镜像比 recorder.js 多出来的 `li → listitem` 分支（真实实现没有）。
- 顺手修的真 bug：`recorder.js` 的 `input` 监听对 checkbox/radio 也记 `fill`（值 'on'），生成 `fill('on')` 在 Playwright 里直接报错，而且和 click 步骤重复。现在加 `FILL_INPUT_TYPES` 白名单（text/search/tel/url/email/password/number/date 系列），只对 INPUT 白名单类型和 TEXTAREA 记 fill；contenteditable 的 input 也一并挡掉（`el.value` 是 undefined）。
- 顺手修的历史遗留：`test_recording_session_rules` 的 `_session()` 手工构造缺 `_context/_paused/_panel_page`，4 个用例一直 error。补齐后**后端录制测试首次全绿：91 项**。
- 真实录制复测（select 无 label / checkbox 无 label / input 带 placeholder）：前两个 primary 变成 `getByRole('combobox')` / `getByRole('checkbox')`，第三个仍是 `getByPlaceholder('搜索')`（排序正确）；checkbox 只剩一条 click，不再有 fill。

## 录制工具栏按钮：审查结论（本轮只读代码，未改动）

按钮链路分层是「前端发意图 → 录制线程 queue 执行 → 注入脚本里的开关决定记不记」，这块没问题。查出 4 个真问题：

1. **断言目标靠 alias 认元素，alias 不去重**（P0，静默错）。`ir.make_target` 的 alias = name||label||placeholder||text||tag 截 40 字，无唯一化；`aliases()` 只去重展示，`_find_target()` 取「最后一个同名」。列表页两行都有「删除」时，下拉只有一个「删除」，断言会绑到最后一行那个，且状态显示「唯一」，没有任何告警。
2. **停止不可逆 + 重新开始静默丢步骤**（P0）。`_finish` 关浏览器；`start_new` 只挡 starting/recording，stopped 时直接替换 `_current`，旧步骤不落库、不提示。`cancel()` 有实现但界面无入口。
3. **手动步骤 page_index 恒为 0**（P1，多标签页断言错页面）。`add_intent_step` 调 `make_step` 不传 page_index，默认 0；`replay._page_for` 也是 `step.get('page_index') or 0`。若录制中途开过新标签页，之后从工具栏加的断言都会落到 page 0。
4. **拾取模式吞点击**（P1）。click handler 在捕获阶段 `preventDefault + stopImmediatePropagation` 后只发 pick，页面不会展开菜单/弹窗，所以想拾取弹层里的元素必须先退出拾取。另：pick 分支在 `state.paused` 判断之前，暂停下拾取仍生效，与「暂停=不记录」的文案冲突。

次要：picks 无列表无删除；三个添加按钮只是同一张草稿卡的三个子集；HUD 有「撤销上一步」而面板没有（`_handle_hud_action` 只处理 undo）。

## 断言按钮（智能断言）实用性评估（讨论，未改代码）

现状链路：`draft.text` → `POST /intent` → `intent.parse_intent` 一次 LLM 调用（SYSTEM_PROMPT 是「只做格式转换」）→ 返回 10 个固定 type 之一 + target(必须是 aliases 里的名字) + value → 前端只读显示「理解为 …」+ 确认插入。

关键事实（都已在代码里核实）：
- 模型输入只有「用户一句话 + session.aliases() 别名列表」，**没有元素类型、当前值、页面 URL、最近步骤**，所以它只能按名字猜目标。
- 解析结果**不可编辑**，`draft.parsed` 与表单字段 `intentType/target/value` 是两套，解析不会预填表单；改完 `draft.text` 预览也不失效（stale）。
- 断言卡里的「拾取元素」`:disabled="!isRecording"` → **停止录制后就拾不了新元素**，而补断言最自然的时机正是录完之后；瞬态元素（toast/loading）更是当场就没了。
- 没有「插入前先验证」的入口，反馈链是 插入 → 停止 → 生成 → 回放 才发现错。
- 类型集合不一致：断言下拉只给 ASSERT_TYPES(7)，但 `/intent` 的 prompt 给模型的是全部 10 种，从「添加断言」进来解析出「等待」也会照样插入。
- 插入后 `draft.value = null`，连续加多条断言每条都要重新走一遍。

待办方向（按性价比）：① 解析结果做成可编辑预填；② 插入前跑一次 `replay._assert` 就地验证；③ prompt 补元素上下文；④（另算）录完自动建议断言。

## 断言按钮四步改造（已实现）

按「① 停止不销毁浏览器 → ② 解析结果可编辑预填 → ③ 页面文字断言 → ④ 验证口径」落地。

1. **停止录制不再关浏览器**（`session.py`）
   - `_finish` 拆成 `_mark_stopped(status, revalidate)`（只结束记录，保留浏览器/面板）+ `_shutdown()`（关面板 context 与浏览器）。`_loop` 停止后继续跑，`_drain_commands` 新增 `close` / `verify`，`stop` 幂等。
   - `_call` 的判断从「状态」改成「线程是否存活」，否则停止后所有命令都会被判「录制已结束」。
   - `_handle_event` 增加 `kind != 'pick' and (paused or status != 'recording')` 就丢弃 → **停止后普通点击不记步骤，但拾取仍然生效**。
   - `snapshot()` 加 `browser_open`；`close` 命令先把 `dict(snapshot(), browser_open=False)` 回给请求线程再 `_shutdown()`（面板就活在那个浏览器里，顺序不能反）。
   - `start_new` 前先 `dispose()` 掉上一轮 stopped 的会话，否则会留下没人管的窗口；新增 `dispose_current()` 给应用退出/测试 teardown。
   - 停止后 60 分钟无命令自动收窗口（`STOPPED_IDLE_SECONDS`）；`_last_activity` 只在命令里 touch，GET 不算。
2. **插入前验证**（新 `verify.py` + `POST /automation/recording/verify`）
   - `verify.check(frame, target, intent)` 用 `pick_for/best_effort` 还原定位，逐类型回答「此刻成不成立」，并回 `actual`（innerText / input.value / 可见性 / URL、整页 innerText）。
   - `session._verify_now`：有目标用目标录制时的 frame（`_find_target_with_frame` 连带取出 `_frame`），没有目标用 `_text_frame(page)`（嵌入模式取被测 iframe，普通模式取 main_frame）；`_current_page()` 取 `context.pages[-1]`。
   - 无目标类型（`page_text_contains`/`url_contains`）必须在 target 判空之前分流，否则会抛「没有名为 None 的元素」。
   - 口径写死成「当前页面状态」：不等待、不重跑，前端结果块里明写「不是回放结论」。
3. **解析结果可编辑预填**：`parseDraft` → `applyParsed` 把 type/target/value/seconds 写进表单，并按结果切 `draft.kind`（模型给 wait_hidden 就从「添加断言」变成「添加等待」，否则下拉没有这个选项）；插入只认表单，`draft.parsed` 只做展示。`formSig`/`parsedSig` 对比出「表单已修改，以表单为准」；`watch(formSig)` 清掉过期验证结果。
4. **页面文字断言** `page_text_contains`：`ir.INTENT_TYPES` / `intent.NEEDS_VALUE` / 前端 `ASSERT_TYPES` 同步；emit 提示词给 RF `Wait Until Page Contains`、PW `expect(page.locator("body")).toContainText`；replay `_assert` 支持 body 断言。顺带把 `intent.build_prompt` 改成逐类型说明（哪些要目标），修掉「模型只能靠猜、把页面提示硬绑到某个元素」。

顺手修的 P1：`add_intent_step` 的 `page_index` 改为按锚点推断（`_page_index_near`），追加就在最后一步的标签页，插在某步后就跟那一步。这改了 `test_recording_replay._record` 的语义 → 断言目标必须换到新标签页上的元素（`新页按钮` / `newtab.html`）。

测试：新增 `test_recording_verify.py`（5 条真浏览器：文字/可见性/值/整页、停止后验证、停止后点击不记但拾取生效）；`test_recording_routes` 补 stop 幂等 / 关闭后失效 / verify 4 条并改 teardown 为 `dispose`；core/emit/replay/session_rules 各补 1-3 条。后端 98（不启浏览器）+26（启浏览器）全绿，前端 build 通过，UI 用 mock 接口冒烟 14 项全过（截图确认卡片布局）。

遗留未做：alias 不去重（同名元素断言会静默绑最后一个）、拾取模式仍吞点击、picks 无删除、插入后的断言不能就地改。

## 别名唯一化 + 拾取穿透（两项遗留已修）

**别名唯一化**（`session._alias_for` / `_alias_key`）：身份按「元素」判而不是按「名字」判，否则同一个按钮点两次会变成两个选项。判据：有唯一主定位时用主定位 desc（两个不同元素不可能同时命中同一唯一选择器）；没有唯一候选时退回 `css` 路径 + 标签 + frame id（同一元素两次操作路径相同，不同行的同名按钮不同）。撞名加 `#2`、`#3`。`_alias_keys` 存在会话里，`__init__` 里初始化；`_handle_event` 在锁内赋值（唯一性要看已录入步骤，属于会话状态）。`ir.ALIAS_MAX_LENGTH=40` 提成常量，加后缀时按长度截断。
新增 `alias_items()`（alias + `hint`「第 N 步 · 点击」+ `desc`），前端下拉换成带右侧灰字提示，否则「删除」和「删除#2」在界面上没法区分谁是谁。

**拾取穿透**（`recorder.js`）：拾取模式下点 `Alt` 时**只拾取不拦截**，让菜单/下拉/折叠面板真的展开，否则里面元素根本拾取不到；不按 Alt 仍然三连拦截（拾取时误点「删除」不能真删）。刻意没做「哪些元素自动放行」的白名单——猜错的后果比现状严重。前端 pick-hint 加了说明。

测试：`test_recording_session_rules.AliasTest` 5 条（同名不同元素分叉、同元素复用、按主定位而非 css 判身份、每个别名解析到自己的元素、alias_items 提示）；`test_recording_verify` 新增 `AliasOnLivePageTest` 2 条真浏览器（两行「删除」→ `删除`/`删除#2`，隐藏第一行后只有 `删除#2` 仍可见）和 `PickPassthroughTest`（普通点击不展开菜单、Alt+点击展开）。后端 103 + 29 全绿，前端 build 通过，UI 冒烟截图确认下拉里两行可选区分。

仍未做：picks 无列表无删除、已插入的断言不能就地改（删除入口有，只是要重填）。

## 定位讨论（战略结论，未改代码）

赛道现状（2026-10 调研）：录制作产物这条路历史上塌过三次——Selenium IDE 停更、Katalon Recorder 2026-09 官方标注"不再维护"、TestProject 2023 被 Tricentis 关停。Playwright 官方已内置 Test Agents（planner / generator / healer，`npx playwright init-agents`，2025-10 起），"AI 生成 PW 测试"会被官方持续吃掉。视觉/自然语言阵营是 Midscene（15k star，aiAssert 非确定性、3-10 倍耗时）、testRigor、mabl、Momentic。RF 侧有 rf-mcp（agent 从零写 .robot）和 robotframework-agent（Agent.Do / Agent.Check，alpha）。

结论：① 本项目不是 codegen 之上套壳，而是重写了录制器（recorder.js + snap + 定位投影），真正的资产是「一套快照 → PW/RF 双框架一致投影 + 回放校验」，这在 RF 生态是空白，官方永远不会做；② 不要在 PW 侧和官方 Test Agents 拼输出质量，那是正面撞车；③ 接 agent 的优先级：回放失败→带证据自愈 > 断言建议（用 verify.py 采样操作前后的变化）> 意图还原/参数化（硬编码值→变量、重复块→关键字）> 从零生成整套用例（不做）。
