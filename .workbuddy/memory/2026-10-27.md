## 生成链路：加规划阶段（recording-planner）

**背景**：用户提出「我自己手动开 opencode 给他定位，他写出来的脚本我能接受，越往这个方向靠越好」。
诊断结论：模型本来就有 ls/glob/grep/read 能力，问题在 `recording-emitter.md` 第一句
「请按下面的录制结果写入一个测试文件」——把 agent 降级成了模板填充器，它不会主动去看项目。

**方案定稿**：录制 IR → planner（只读，扫项目出任务书）→ emitter（按任务书写）→ 校验。
用户明确：第一版只允许写单个文件，权限分档（新建/修改/配置分级）不做，后续按实际效果优化。

  硬规则：不许编造 file/symbol/import，没有封装就留空数组。

## 生成链路二期：规划独立成一步（plan → 人审 → 执行）

**事故现象**：生成报「agent 没有写出目标文件」，但 `tests/ai-chat/test-corekg.spec.ts` 确实写出来了。

**根因（三条叠加）**：
1. planner 读了 `playwright.config.ts`（`testDir: './tests'`），把任务书里的 `target_path`
   从 `test-corekg.spec.ts` 改成 `tests/ai-chat/test-corekg.spec.ts`，理由写在 `project_style.notes`；
2. emitter 照任务书写到新路径，后端仍按请求里的旧路径验收 → 找不到 → 报「没写出」；
3. 写权限白名单里有 `**/目标文件名`，实际效果是「任意目录的同名文件都能写」，所以它写得进去。
   这条 glob 必须删掉，只留精确相对路径 + 绝对路径。

**用户定的三条**：建议路径只提示 + 一键采用；写入的唯一入口是任务书的「按此执行」；
「执行」= 批准任务书开始写脚本（试跑不做）。另外要求能**选中任务书里的片段写意见**。

### 改动

- `emit.py`：
  - 拆成 `plan()`（只读，失败直接抛 EmitError，不再降级）和 `generate(plan=...)`（不再规划）。
  - `_normalize_plan`：`target_path` 强制写回请求值；模型改过的路径降级成
    `target_path_suggestion` + `target_path_reason`。
  - `plan_matches_steps` + `steps_signature`：序号 + 类型 + 元素别名，删一步再补同名步骤也判过期。
  - `_payload` / `_prompt` 加 `plan_feedback`，用户意见优先于任务书。
  - 目标文件缺失时 `_missing_target_details` 用 `guard.changed` 报「实际写到了哪些文件」。
- `progress.py`：加 `mode`（plan/write）与 `PLAN_STAGES`；规划自己的 4→92%，结束文案「任务书已就绪」。
- `routes/recording.py`：新增 `/recording/plan`；`/generate` 必须有 plan（缺失 400、过期 409 `plan_stale`），
  体积上限 64KB；plan/generate 共用 `_prepare_generation`。
- `opencode_runner.py`：白名单删 `**/rel`。
- 提示词：planner 明确「target_path 原样返回，建议写 suggestion/reason」；emitter 明确「忽略 plan 里的路径」。
- 前端 `Recording.vue`：生成按钮改「生成任务书」；任务书卡片（项目风格 / 建议路径 + 采用 / 复用清单 /
  逐步做法 / 风险 / needs / 意见列表）；选中文字浮出「就这段写意见」；执行只在任务书里。
  `api.planRecording` 超时 600s。

### 未核实根因修复：pointerdown 预计数（18:40）

- 根因：`recorder.js` 在 click（冒泡后）才发事件，Python 计数时元素已被点击自己带走；
  叠加 `PUMP_MS=150`（binding 回调只入队），计数最多晚 150ms。
- 方案：`pointerdown` 先发 `precount` → `_handle_precount` 数候选并缓存（TTL 5s、最多 8 条），
  click 用同一个 `data-autocase-target` mark 取走；没等到 click 就自然过期。
- `PUMP_MS` 150→30，让预计数赶在 mouseup 之前跑完；实测按住 60ms 也能命中。
- 同名元素快照（`matches`）也在按下时取：点完就没了，这份是「当场选第几个」的依据。
- `vanished_after`：click 时若元素已被带走，标出来；前端不再弹确认卡（否则会框到剩下的同名元素），
  徽标提示补一句「计数取自按下鼠标那一刻」。
- `test_recording_precount.py` 5 条（真实浏览器 + 缓存单测）；录制相关 125 条、全套 307 条全绿。
- 生效需重启后端；当前 13 步录制会丢。

### 写入路径改为「规划提名 + 用户确认」（19:00）

**根因（240s 规划超时）**：不是网络卡死。opencode 库里 4 轮实测 7.1s / 10.2s / 102.3s / 120.3s，
模型速度稳定 55-60 tok/s，第 3-4 轮 reasoning 各 18959 / 23530 字符，JSON 一个字没写就被 abort。
触发点是 `target_path=test-corekg.spec.ts`（根目录）与项目 `testDir: './tests'` + 已存在的
`tests/ai-chat/test-corekg.spec.ts` 冲突：模型想改、提示词不许改，它就在 reasoning 里反复权衡。

**改动**
- `emit.py`：新增 `target_problem(workspace, path, framework)`（工作区内 / 扩展名 / 禁 node_modules
  与配置文件名 / 单文件）；`_prepare` 允许空路径；`_normalize_plan` 改为「用户填了就锁死、留空就采纳
  模型提名的路径并校验」；`_project_facts` 把 `test_dir` + `recent_tests` 提前塞进 payload；
  `plan()` 返回 `chosen` 标记「位置是 AI 选的」。
- `routes/recording.py`：`_prepare_generation` 允许空路径；generate 用
  `ctx.target_path or plan.target_path` 并重新校验（plan 是回传值，不能信）；`plan` 与写手提示词里的
  路径强制同步；`_keep_failed_record()` —— 失败但文件被动过时留一条 `failed` 记录，可回滚。
- `records.py`：`create(status=)` / `revert` 支持 `failed`（不校验哈希，直接还原）。
- `detect.py`：`_is_artifact_copy()` 过滤 `autocase/runs/<时间戳>/` 下的产物副本，别当项目写法推荐。
- `Recording.vue`：`target_path` 变可选且**不再持久化**（上次的值会把路径锁死）；任务书卡片
  「写入位置」可编辑 + 「AI 按项目约定选的」标记 + 手改时提示 import 可能失效；执行用 `planTarget`。
- `recording-planner.md`：改成「非空→原样返回；空→你来定 + 一句依据」，禁止为路径反复权衡。

reason「同站点同流程的参考文件在 tests/ai-chat，且被 chromium project 收集（testDir=./tests）」。
