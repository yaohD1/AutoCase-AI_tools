## 修正：浮层必须用 closed shadow root（会污染文本定位）

- 实测复现：`open` shadow root 下，Playwright 的 text 引擎会穿透进面板。面板每行 `.ac-name` 显示的就是元素名，
  于是同名候选被多算：纯文本 `div`「提交订单」第二次点击时 `getByText('提交订单', exact=True)` 从 1 变 2，
  主定位从 text 掉到 css，状态 unique → fragile（误标黄；更极端会判不唯一）。
- 修法：`recorder.js` 的 `attachShadow({ mode: 'closed' })`。closed 树 Playwright 不可见，验证同一场景 text count 回到 1、status unique。
- 影响面确认：css 候选由我们自己 `cssPath()` 生成且从被点元素往上走，HUD host 挂在 `documentElement` 下、内容在 shadow 里，不受影响；
  XPath 引擎不穿 shadow；徽标同样在 shadow 内。生成/回放用的是新浏览器，根本没有 HUD。
- 自测钩子：`window.__pwHudSnapshot()`（闭包内读渲染状态，closed root 外部拿不到内容时用）。
- 回归：撤销按钮用坐标点击仍可用（步骤 3→2，且该点击没被录成步骤）；34 个测试通过；前端 build 通过。

## 修复：浮层「收起」按钮点了没反应

- 原因：`.ac-head` 上的拖拽逻辑在 `pointerdown` 里 `setPointerCapture` + `preventDefault`，
  导致后续 click 被重定向到 header，header 里的 `.ac-fold` 按钮收不到 click（真实鼠标点无效，用 JS `.click()` 才能过，所以之前自测没发现）。
- 修法：`enableDrag` 的 pointerdown 开头 `if (e.target.closest('button')) return;`。
- 顺带修：宿主宽度从固定 `300px` 改 `max-content`，否则收起成胶囊时会贴在面板区域左边缘而不是右下角。
- 实测（真实 `page.mouse.click`）：点「‒」→ collapsed=true，胶囊 93×32 贴右下；点胶囊 → 展开；header 空白处拖动仍可用（962,540 → 742,420）；HUD 上的点击没有被录成步骤。34 个测试通过。

## 修复：窗口最大化/全屏后右侧空一大块

- 根因：`browser.new_context()` 默认给 **1280×720 的 viewport**（Playwright 用 CDP Emulation 覆盖渲染尺寸），所以不管窗口多大，页面永远按 1280 渲染 —— 最大化到 2048 后右边整块是空背景。
  实测对比：`--window-size=1600,900` 时默认 context `innerWidth=1280`，`no_viewport=True` 时 `innerWidth=1600`。
- 修复 1：录制 context 改为 `new_context(no_viewport=True)`，页面跟随真实窗口；顺带让 split 模式也更接近真实浏览器。
- 修复 2：嵌入模式**先最大化窗口再 goto**（原来加载后才最大化，被测页面按小尺寸完成了首次布局）。
- 修复 3：`body` 默认 8px margin 导致 16px 溢出（右侧多一条空白 + 滚动条）。App.vue 在 panel/embed 模式给 body 加 `.immersive { margin:0; overflow:hidden }`（用 watchEffect 切 class，不改全局默认值）。
- 修复 4：面板宽度加夹取——窗口变窄时自动收，保证被测页面至少 900px（`resize` 监听 + 拖拽上限）。
- 验证：2048×1152 下 `docScroll == [2048,1152]`、`body margin 0`、iframe 1446 + 面板 600；录制流程回归正常（iframe 内点击仍被记录）。
