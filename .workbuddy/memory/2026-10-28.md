## 定位 exact 丢失事故（已修）

- 现象：录制时 `getByLabel('密码')` 判定唯一，运行时 strict mode violation。
- 根因：`locators.py` 用 `spec.kwargs={'exact': True}` 数 count，但 `desc` 是手写字符串 `getByLabel('密码')`，
  写手照抄 desc；`emit._fmt` 对 Playwright 直接返回 desc。计数口径 ≠ 下发口径。
- 实测（ai.test.yygu.cn 登录页切换后）：`getByLabel('密码')`=2（表单项 div + input），exact=1。
- 为什么没暴露：回放 `replay.py:82` 用 `spec['kwargs']` 执行（带 exact），报告里的 `syntax` 却取 desc，
  报告和产物看起来一致，实际只有生成这条丢了 exact。
- 修法：`locators.py` 新增 `render_pw()` / `_pw_spec()`，desc 由 method+args+kwargs 渲染成可粘贴的 JS，
  参数只存一处。role 的 desc 从 Python 风格 `name='x'` 改成 `{ name: 'x', exact: true }`，
  去掉写手的翻译环节（exact 就是在翻译时丢的）。
- 影响：label / placeholder / text / role 四种候选都补上 exact；RF 组走 xpath args，不受影响。
- 测试：新增 4 条（desc==渲染、参数不许丢、多行文本保持转义、desc 里不许出现 `name=`）；
  全量 341 条通过。真实页面验过 4 条 desc 都 count=1，旧写法 `getByLabel('密码')`=2。
- 已知限制：`getByText` 对跨子节点的多行文本（含 exact）永远 0 命中——录制时 count=0 会被跳过，不生成。
- 生效需重启后端。

## 内网自签名证书导致录制打不开（已修）

- 现象：`https://192.168.123.135` 这类内网系统，「录制打不开页面」。
- 根因：`session.py` 建 context 时没开证书忽略，Chromium 报 `net::ERR_CERT_AUTHORITY_INVALID`。
  默认布局是 embed，外壳页（AutoCase）能开，但被测系统的 iframe 变成
  `chrome-error://chromewebdata/`；`_is_app_frame` 只认 base_url 的 origin，不认这个 URL，
  `_wait_app_frame` 空等 25s 返回 False 后**照样把状态置成 recording** —— 用户看到的是「录制中」+ 一张错误页。
- 实测（本地自签 HTTPS 服务）：默认 context `Page.goto: net::ERR_CERT_AUTHORITY_INVALID`；
  `new_context(ignore_https_errors=True)` 正常；iframe 场景同样只有加参数才加载出来。
- 修法：
  - `session.py:711` 录制 context 加 `ignore_https_errors=True`（面板 context 也加）。
  - `replay.py:299` 回放 context 同样加，否则回放会把这个错误报成「定位失效」。
  - `_wait_app_frame` 改为返回 `loaded/error/timeout`，并在循环里用新增的 `_error_frames()`
    检测 `chrome-error://`；`_run` 收到 error 就抛 RecordingError
    「被测系统没有打开：<url> 在浏览器里显示的是错误页。常见原因：HTTPS 证书不受信任、地址或端口不通、内网不可达」。
    timeout 仍然照旧放行（慢站点不受影响）。
- 测试 `backend/test_recording_https.py` 5 条：对照（不加参数必失败）/ 录制能开 / 嵌入 iframe 能开 /
  回放能开 / iframe 打不开时报错而不是静默开始。反向验证：临时去掉参数后录制与回放两条如期失败。
- 全量 356 条通过。
- 产物侧提醒：目标项目 `playwright.config.ts` 的 `use` 里仍需 `ignoreHTTPSErrors: true`，
  否则生成出来的脚本在那边跑同样会被证书拦住（不属本仓库，未改）。

## X-Frame-Options 导致嵌入模式录制打不开（已修）

- 现象：`https://192.168.123.135` 录制窗口里显示「192.168.123.135 拒绝了我们的连接请求」，
  且能在错误页上点出两条步骤（alias 就是那句错误文案）。
- 根因：该站 nginx 返回 `X-Frame-Options: SAMEORIGIN`。默认布局是 embed
  （外壳 `http://localhost:5173/recording` + iframe），跨源被拒 → iframe 变
  `chrome-error://chromewebdata/`。Chrome 对「连接拒绝」和「被 XFO 拒绝」用同一句中文，
  所以看起来像端口不通。
- 次因：`_wait_app_frame` 里 `wait_for_load_state('domcontentloaded')` 对错误页同样成立，
  错误页被判成「已就绪」，于是 status=recording，用户还能在错误页上点出假步骤。
- 修法：
  - 新增 `recording/embedding.py`：`frame_block_reason(url, shell_origin)` 读响应头判断
    `X-Frame-Options`(DENY/SAMEORIGIN) 与 CSP `frame-ancestors`（`none`/非 `*`/非外壳源）；
    HEAD 405/501 回退 GET；连不上返回 None（预检失败不挡录制）；不走系统代理。
  - `routes/recording.py:start_recording`：layout=embed 时预检，命中改 `split`（主窗口直接开
    被测页面 + 另开面板窗口），响应里加 `notice` 说明原因。
  - `session.py`：新增 `_frame_failed()`，`_wait_app_frame` 在 load 后复查 frame.url 是否
    `chrome-error://`；错误文案补上「禁止被 iframe 嵌入」这一原因。
  - 前端 `Recording.vue`：`startRecording` 收到 `notice` 弹 warning（10s，可关闭）。
- 实测：真实站点预检返回 `X-Frame-Options: SAMEORIGIN`；对照（localhost:5173）返回 None；
  split 布局起真实会话 → status=recording、主窗口 `https://192.168.123.135/#/login`、
  面板窗口 `localhost:5173/recording?panel=1`。
- 测试 `backend/test_recording_embedding.py` 11 条（XFO deny/sameorigin、无头、
  CSP none/star/外壳源/他源、HEAD 405 回退 GET、连不上放行、路由改布局与 notice）。

### ② 候选交叉验证（`data-autocase-target` 用起来）
问题：`_count` 以前只在 `count > 1` 时算 index，`count == 1` 直接当成「命中目标」。
但 count 只回答「匹配了几个」，不回答「匹配的是不是用户点的那个」。
- `session.py`：`FIND_INDEX_JS` 改为返回 `{index, relation}`（self / ancestor /
  descendant / other / gone）；`_count` 对 `count >= 1` 全部验证，`count == 1` 时先
  `get_attribute` 快查（命中就只多一次往返），不命中才 `evaluate_all` 细判。
  **`count == 1` 不写 `index`**——index 是多匹配时的序号，写 0 会让前端渲染成 `.nth(0)`。
- `locators.py`：新增 `hits_target()` / `false_positive()`；`rank` / `pick_for` /
  `best_effort` 全部排除 `relation == 'other'`；`rank` 在「唯一候选全指错」时回退并标
  `suspect`（不判 ambiguous，否则用户只看到「未核实」却不知为什么）；`status_of` 加 suspect。
- `ir.py`：candidates 带上 `relation` 传给前端。`emit.py`：`_candidates_for_prompt` 剔除
  假阳性，`ancestor`/`descendant` 标 `hit` 字段。
- 前端：`hitsTarget()` / `pickFor()` 与后端同构；新增 `suspect` 状态（红色徽标「定位存疑」、
  统计行、`needsLocConfirm` 也弹确认框）；`withNth(desc, index, count)` 加 `count <= 1` 保护。

## RF 定位 P1：序号内联（消掉「绿着点错行」）

### 问题
`LOCATOR_RULES` 让写手把序号拼进字符串：
`robot-selenium 写 xpath=(<locator 去掉 xpath= 前缀>)[n+1]`。三个必坏出口：
1. 忘改 → Selenium `find_element` 多匹配**取第一个且不报错**，脚本绿着点错行；
2. 候选是 `css=`（`rf_css` 兜底）时，按规则拼出 `xpath=(css=...)[2]`，语法错误；
3. 表达式带 `[` / `|` 时括号位置容易错。

### 实现
- `locators.inline_nth(locator, index)`：唯一拼装点。只处理 `xpath=` 前缀，
  产出 `xpath=(expr)[n+1]`；index 为 None/-1、css=、空表达式一律原样返回 `(locator, False)`。
- `emit._fit_nth(locator, index, framework)`：RF 才内联，Playwright 保持 `.nth(n)` 交给写手
  （方法调用不易错，且 desc 还要用于界面预览，不该混进执行细节）。
- `emit._locator_info`：`chosen` / `ambiguous` 两个分支调用 `_fit_nth`，内联时加 `nth_applied: True`；
  `nth` **保留**（前端「取第几个」、`degraded` 统计、注释都要用），只是不再参与拼接。
- `emit._candidates_for_prompt`：候选取的 locator 也内联——否则主定位安全、备选仍是裸串，
  写手从清单里挑备选就又回到「自己拼」。
- `emit._steps_for_prompt`：`nth_applied` 只在内联时为真才输出，避免 payload 里出现无意义的 false。
- `LOCATOR_RULES` 重写为四条分支：nth_applied 原样用（禁 .nth()、禁再包一层 [...][n]）/
  PW 写 .nth(n) / css 多匹配写 TODO / 都没给就取第一个加注释。旧的 `去掉 xpath= 前缀后的表达式` 已删。

## RF 定位 P2：分清「业务键」和「框架自动生成 id」

用户：「你觉得有必要做就做吧」→ 做了。实测发现原判据**两个方向同时错**，
比计划书里写的还严重。

### 旧判据
`_DYNAMIC_ID = re.compile(r'^el-id-|\d{3,}')` + `search` = 「数字多就是动态的」。
- 误杀：`order-20261028-001`、`user-100`、`order-2026`、`btn-1234` 全被扔，退到文本/css；
- 漏放：`:r1:`（React 18 useId）、`react-select-3-input`、`rc-tabs-0-tab-2`、`mui-12345`、
  `ext-gen1234`、`gwt-uid-42`、`j_id_5`、`ember1234`、`headlessui-*`、`radix-*` 全留着；
- `input-0` / `tab-2` 数字不足 3 位，逃过正则，当干净 id 用。

### 新判据（三级）
1. `_DYNAMIC_ID` 改为**框架前缀白名单**（`:r..:` / `el-id-` / `react-select-` / `react-aria` /
   `downshift-` / `headlessui-` / `radix-` / `rc-<comp>-` / `mui-` / `ext-gen` / `gwt-uid` /
   `j_id` / `ember<数字>`）→ 丢弃。这类重新挂载必变，回放没有任何补救空间。
2. `_ID_WITH_NUMBER = \d{3,}` 或 `_SEQUENTIAL_ID = ^(input|tab|item|field|row|col|btn|...)[-_]?\d+$`
   → `rf_id_loose`，既不丢也不当首选。
3. 其余 → `rf_id`。

### 排序（与计划书不同，已在文档里说明理由）
`rf_testid → rf_id → rf_name → rf_aria → rf_label → rf_id_loose → rf_xpath → rf_row_scoped → rf_css`
计划书原写「放 rf_xpath 之后」，理由是「row-101 数据变了可能命中另一行」——这条不成立：
id 在 HTML 里唯一，数据变了是**找不到**，不是命中别人。既然不会静默点错，它就该排在文本匹配
之前（文本会因文案微调失配，也可能命中提示语里的同名字）。真正会「命中另一行」的
`row-0` / `item-3` 已被 `_SEQUENTIAL_ID` 归到 loose，且让位给 name/aria/label。

核心取舍写进代码注释：**丢弃的代价是退到 css 结构路径（会静默点错），保留的代价最坏是
回放时找不到元素（明确失败、好查）**，所以保留。

## 补两个跨框架的快照层洞（class 名字候选 + 结构路径唯一性自检）

用户结论先行：AI 直接给定位这条不做（实测 1/4 成功，比现有 3/4 差），改补两个真正的缺口。

### 洞一：class 里有名字却从来没用
真实快照里大量控件无 role、无 aria、无文本，唯一身份线索是 class：
`_sidebarListHeaderAdd_ce5l0_53`（Vite CSS Modules `[name]_[local]_[hash]_[line]`）。
哈希每次打包都变，名字不变 → `[class*="_sidebarListHeaderAdd_"]` 比 `div:nth-of-type(3) > div > button` 稳。

- `locators.class_stem(token) -> (stem, exact)`：剥哈希留名字。
- `[class~=]` 用于整词（`user-card__name`），`[class*=]` 用于剥过哈希的前缀。
- 三个必须挡的噪音：Tailwind 工具类（`p-3`、`w-[15.368px]`）、组件库前缀（`ant-`/`el-`/`t-`，
  **正则里必须带分隔符**，否则 `t` 会吃掉 tab/title/tooltip）、构建期类名（`css-1l86wfl`、`_ngcontent-c12`）。
- 哈希不一定含数字：`fxrlp` 靠「短短小写串」认；`active`/`primary` 短但是状态名，要留住。
- RF 对应 `rf_class_part`：`//*[contains(@class,'x')]`；整词用 `concat(' ',normalize-space(@class),' ')`（XPath 没有 `~=`）。
- 排位：两套框架都是「文本之后、css 之前」。

### 洞二：cssPath 从不自证唯一
旧版 6 层封顶、从不验证，`div > div > ... > button` 这种「每层都没重名兄弟」的路径会命中一堆。
改成「最短且唯一」：每加一层 `querySelectorAll` 数一次，命中 1 个立刻停手；上限 12 层；
shadow root 里在同根内数。

实测（`ai.test.yygu.cn` 主壳 400 个可交互元素）：
- 不唯一：9/400 → **0/400**；平均路径 6.0 段 → **2.9 段**；单次快照 0.007ms → 0.97ms（每次点击 ≈ +2ms）。

### 改动文件
`locators.py`（class_stem/class_stems/class_selector/class_xpath + build_specs + KINDS）、
`recorder.js`（cssPath 重写 + `class_raw` 采集，240 字符上限）、`emit.py`（提示词说明 `[class*=]` 是故意的）、
`Recording.vue`（PW_ORDER/RF_ORDER + 状态提示）、`test_recording_locator_parity.py`（镜像 SNAP_JS 同步）。

### 验证
`test_recording_class_part`（16）、`test_recording_css_path`（6，**直接注入真 recorder.js** 点一下再读 emit 的快照；

## 「页面已经变了，没法选第几个」——用记录下来的 URL 回去，不用浏览器后退

痛点：点了不唯一的按钮，弹窗出来时页面已经跳走，框不出元素。
旧退路「稍后再选」是假出口：那时页面只会更变，永远确认不了。

### 先实测，否掉了想当然的方案
在 ai.test.yygu.cn 上跑真实流程：

| 测的 | 结果 |
|---|---|
| `go_back()` 从 /docs 后退 | URL 落到 **/login**（不是 /global），`go_forward` 回不去 /docs |
| `goto('/global')` | 恢复完整：textbox 2、`_itemMenu_` 796，和点击前一致 |
| `click → URL 变化` | **12.3 ms** |
| `click → 聊天输入框消失` | **211 ms** |

结论：**浏览器后退不能用**（SPA 登录跳转留下的历史条目会把它带偏）；
「点击前截图」也悬（30ms 泵 + 60~80ms 截图抢不过 211ms）；
**用地址重开是干净的**。

关键发现：每步早就存了 `step['_doc']['url']`——recorder.js 在 **capture 阶段**读
`location.href`，早于应用路由，所以它正是「点击之前」的地址。不用新采数据。

### 实现
- `session._goto_doc_now(no)`：step._doc.url → `frame.goto` → 等 900ms 让列表拉回来。
  step 上的 frame 可能已销毁，失败就退到 `_app_frame()` 再试一次。
- **导航静音**：`_nav_mute_until = now + 4s`。不加的话每回去看一次就多一条 goto 步骤。
  静音分支里仍然要更新 `_last_url` / `_doc_stamp`，否则后续 same_url 判断错位。
- `_goto_back_now()`：回到离开时那一页（`_return_url` 只记第一次，连看几条不会覆盖）。
- 接口：`POST /recording/goto-doc {no}`、`POST /recording/goto-back`。
- 弹窗：highlight 返回 `not_found` / `frame_lost` 才给「回到这一步的页面」
  （`no_candidate` 这类重开也没用）；回来重新框，选完给「回到刚才的页面」。
- 停止后：检查清单那行加「N 步待确认 · 逐条看」，把 `page_gone` / `unverified` 也纳入队列
  （`needsLocConfirm` 原本把这两种排除了，因为当时框不出来——现在能回去看了）。
- 提速：前端接上**一直存在但从未被使用**的 `/recording/events` 游标接口，
  录制中 200ms 拉增量（几十字节），有变化才拉完整快照。原来固定 1s 拉整包，
  弹窗最坏要等 1 秒——页面早跳走了。

### 坑
- `closeLocConfirm` 必须 await `goto-back` 再开下一条，否则下一条在跳转途中框选，一个都框不到。

## 拾取元素补上「看得见」：悬停高亮 + 模式提示 + Esc 退出

用户反馈：点「拾取元素」后去页面上选，交互太弱，想要浏览器 F12 那种鼠标划过有色块。
诊断下来是三层反馈全缺：

1. 开了拾取，页面上什么都没变（光标还是箭头，划过无反应）——提示只写在编排面板里，眼睛在浏览器上；
2. 点完只有操作点闪 1.7 秒的小徽标，容易被页面新内容盖住；
3. 回面板没有任何「已拾取」清单（顺手发现：前端压根没展示 picks，只在「添加断言」下拉里露头）。

用户选了 A（悬停高亮）+ B（模式提示/Esc），C（拾取清单）和 D（悬停算定位唯一性）先不做。

### 实现要点

**拾取层独立 shadow host**（`__autocase_pick`，closed root，z-index 2147483646）：
不复用 HUD 的 shadow —— 两者生命周期不同，HUD 按帧重建会把拾取层一起清掉。
内部 box / tag / flash / bar 全用 `position:fixed` + 视口坐标，滚动时重算（不用叠 scrollX/Y）。
host 只有 `position:fixed` 没有 transform，内部 fixed 才继续相对视口。

**「框住的 == 会拾到的」是这件事的全部意义**：
`pickHoverTarget(e)` 与 click 的拾取分支一字不差（`closest(INTERACTIVE) || e.target`），
**不做 liftToClickable**——拾取是「登记一个元素供以后引用」，不是「点它」，
为了能点到而换成外层容器会让定位变差。照抄 F12 直接框 `e.target` 会框住 13×13 的图标、
实际登记 80×36 的按钮，比没有高亮更让人困惑。

**Esc 必须走后端**：开关存在 Python（工具栏、轮询都读它）。
页内先关本地再通知 --> 后端没收到就「页面已退出、面板还写退出拾取」。
`window.__pwHudAction('pick-off')` → `_handle_hud_action` → `_set_pick(False)`。
`_handle_hud_action` 里必须**提前 return**，否则会掉进 undo 分支把上一步删掉（有测试盯着）。

**events 接口补 pick / paused**：这两个状态能在页面里就地切换，游标不动，
只比「有没有新步骤」发现不了。前端 `pollRecordingEvents` 单独比这两个字段。
另外停止后事件流从 200ms 降到 1s 继续跑（原来只在录制中跑），否则 Esc 退出后要等 2 秒轮询。

**跨页面保留**：`_handle_navigated` 里重发 `__pwSetPick(true)`。
不重发的话 Alt+点开下一页之后高亮就没了，人还以为拾取自己退了。

### 两个坑（都是测试抓出来的）

1. **标签测尺寸必须在 display:block 之后**。原代码量 `offsetWidth` 时标签还是 `display:none`，
   量到 0 → 位置算成「压进框内」。断言 `tag.top >= box.top + box.height` 直接把它逼出来了。
2. **标签会压在顶部模式条上**。默认位置与模式条矩形相交时翻到框下方（`pickBarBox` 缓存 + resize 重算），
   元素贴底时再兜底压回视口内。

### 其他细节
- 十字准星用 `document.adoptedStyleSheets` 注入（CSP 拦不住），退出按原路摘掉。
- 点中闪 0.9 秒绿框：高亮「啪」地消失会让人分不清拾到还是点空。
- 矮 frame（innerHeight < 240）不显示模式条，嵌入模式下不会挤掉半屏内容。
- 悬停只渲染，不产生任何事件；`isHudEvent` 的 mousemove 直接收框（鼠标在面板上不算悬停页面）。

### 实测（真实系统 ai.test.yygu.cn，1440×900，1320 个采样点）
mousemove 处理：关闭 **0.068 ms** → 开启 **0.089 ms**，多吃 0.02ms，帧率无感。
截图核对过图标按钮 / 文本域 / 导航项 / 用户入口四种元素。
